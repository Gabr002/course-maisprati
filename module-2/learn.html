Tópico 01

Anatomia do Documento & Fundamentos Web

Todo ecossistema web escalável inicia com uma fundação robusta. A declaração <!DOCTYPE html> instrui o navegador a operar no Modo Padrão (Standards Mode), garantindo que a renderização da página siga rigorosamente as especificações do W3C e evite comportamentos incompatíveis (quirks mode).


O atributo de idioma na raiz (<html lang="pt-BR">) é crítico para o SEO (Search Engine Optimization) e constitui um pilar fundamental da Acessibilidade (A11Y), pois garante que sintetizadores de voz e leitores de tela adotem a pronúncia correta do idioma do usuário.

💡
Visão Pro de Engenharia: O bloco <meta name="viewport"> é o responsável pela responsividade em dispositivos móveis, adaptando a escala inicial da viewport do navegador ao hardware físico do usuário sem perda de fidelidade de renderização.
Esqueleto Padrão 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" 
          content="width=device-width, 
                   initial-scale=1.0">
    <title>Título Acadêmico</title>
</head>
<body>
    <h1>Olá mundo!</h1>
    <p>Primeiro passo com HTML5.</p>
</body>
</html>
Tópico 02

Hierarquia de Conteúdo & Tags Semânticas

A regra de ouro da engenharia Front-end é: "Use a tag pelo seu significado semântico, nunca por como ela parece visualmente". A formatação visual deve ser delegada integralmente ao CSS. As tags são contratualmente a estrutura lógica do documento para navegadores, motores de busca e ferramentas assistivas.

Hierarquia de Títulos (h1 a h6)

Estrutura Visual

H1: Título Principal (Único por página)

H2: Subtítulo do Setor

H3: Seção Especificada

H4 a H6: Subdivisões Granulares

Diferenciação semântica vital: O elemento <strong> indica importância e gravidade, enquanto o elemento <em> representa ênfase tônica na leitura. Não devem ser substituídos pelas tags antigas <b> ou <i> quando a finalidade for transmitir significado.

Tópico 03

Ganchos Arquiteturais: Classes vs. IDs

Atributos globais como id e class funcionam como as convenções de contrato (etiquetas) entre o Markup HTML, as folhas de estilo CSS e a lógica JavaScript. Compreender sua especificidade é a chave para evitar código ilegível ou conflitos de estilo.

Exemplo do Curso Módulo 02

Esta linha é especial (via .destaque)

Esta é uma linha comum e sem estilo diferenciado.

Esta também é especial (reutilizando a classe)

Elemento Composto: Tenho um id="aviso" (Único) e duas classes simultâneas (class="destaque caixa").

Boas Práticas para Sênior:

  • IDs são Exclusivos: Um id deve ser absolutamente único dentro da página. Use-os estrategicamente para ímãs de ancoragem ( links hash #), vinculação de labels e controle cirúrgico de JavaScript.
  • Classes são Reutilizáveis: Projetadas segundo metodologias modernas (como BEM ou Design Systems) para definir componentes estilizados de forma modular, mantendo o código DRY (Don't Repeat Yourself).
Tópico 04

Estrutura e Semântica de Dados Tabulares

Tabelas servem exclusivamente para o mapeamento de dados multidimensionais ou relacionais (como planilhas, relatórios financeiros ou diários de notas) e nunca para diagramação de layout de tela.

♿
Foco em Acessibilidade (WAI-ARIA & A11Y): A utilização da tag <caption> para descrever a finalidade da tabela, juntamente com o atributo scope="col" ou scope="row" no elemento <th>, possibilita que deficientes visuais utilizem leitores de tela para associar sem esforço os dados numéricos às suas respectivas colunas e linhas.

Tópico 05

Coleta de Dados & Interfaces de Usuário (Forms)

Formulários são o principal ponto de contato e interatividade entre a interface do usuário e os serviços de backend. Uma marca registrada do desenvolvedor de alto nível é vincular indestrutivamente o texto explicativo (<label for="id-do-campo">) ao controle correspondente, ampliando o tempo de resposta em telas sensíveis ao toque e eliminando barreiras cognitivas ou de acessibilidade.

Arquitetura & Boas Práticas:

Por que os Labels salvam a UX?

Ao clicar no texto do label, o campo correspondente com o id idêntico ao for="" é focado e ativado instantaneamente. Isso aumenta drásticamente a Área de Toque (Touch Target) para usuários em celulares.

Validação Nativa HTML5

O atributo required e o uso dos tipos de dados adequados na tag input (type="email", type="password", type="tel", etc.) permitem que o próprio motor do navegador atue como uma primeira camada protetora (Front-line Shield), validando o formato antes de autorizar o envio das requisições para o back-end!
